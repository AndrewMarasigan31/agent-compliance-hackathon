## Codebase Patterns
- dayAssignments state shape is `Record<string, Record<number, string>>` (nested: agentName → beatId → day); use Object.entries to flatten for cross-agent logic
- Jest config option for running setup files after test env is `setupFilesAfterEnv` (not setupFilesAfterFramework or setupFilesAfterEach)
- Tests live in beat-planner/__tests__/ (component tests use jsdom env; API route tests use node env — configure per-test with @jest-environment docblock)
- Dashboard state uses `UploadResult` interface defined locally in page.tsx (not in types/index.ts); now uses `agents: string[]` instead of `agentName: string`
- Build command: `npm run build` in beat-planner/ runs both typecheck and compilation
- Types in beat-planner/types/index.ts are shared across components and API routes
- BeatResult is the core domain type — extended with assignedAgent for multi-agent support
- DayAssignments type: `{ [agentName: string]: { [beatId: number]: string } }` is the shape for multi-agent scheduling
